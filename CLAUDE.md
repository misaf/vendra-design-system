# Vendra Design System — working rules

1. **Templates are the source of truth.** `templates/storefront-*` is the only maintained storefront. Keep page copy, behavior and styles with each template; shared examples and helpers live under `templates/`.
2. **Maintain shared storefront code in `templates/_shared/`.** Header, footer, menu and layout markup have their own HTML files; `routing.js` owns URL helpers, `navigation.js` owns shell/menu values, `page-lifecycle.js` owns responsive state/focus/SEO, and `formatting.js` wraps number/currency formatting; `catalog.js` owns sample products and `delivery.js` owns delivery rules. Run `npm --prefix templates run build` after editing shared files or template classes. Install the locked Tailwind development dependencies with `npm --prefix templates ci` on first setup. Use `npm --prefix templates run dev` for Vite preview with automatic rebuilds. Runtime assets are shared from `templates/_runtime/`; do not duplicate runtime JS or CSS in page folders. Page-specific `logic.js`, `copy.js` and `styles.css` are maintained sources, compiled/generated into the shared runtime and HTML. Never edit generated sections in a page. Page markup stays in the marked editable regions of each `Storefront*.dc.html`; page behavior lives in adjacent `logic.js` and regenerates into `GENERATED PAGE LOGIC`. Bilingual page copy lives in each page folder’s `copy.js` and regenerates into `GENERATED PAGE COPY`; Use Tailwind utilities first for storefront presentation; custom page CSS is reserved for contextual/component exceptions in adjacent `styles.css` and builds into one shared runtime stylesheet. Genuinely shared translations stay in `_shared/translations/`. See `templates/README.md`; verify with `npm --prefix templates run check` and `npm --prefix templates test`.
3. **Keep `_ds_bundle.js` lean.** Every `.js`/`.jsx` outside `templates/` is compiled into the bundle. Scratch scripts, generators and sample data must use a `.txt` suffix (loaded via `<script type="text/babel" src="….txt">`) or live under `templates/`. Shared runtime helpers go in `components/utils/`. Never put a second React/Babel copy outside `templates/_vendor/`.
4. **Tenant themes must pass contrast.** Any new or changed `tokens/tenants/*.css` must pass all six Theme builder checks (`guidelines/theme-builder.html`) and the Colors → Contrast card with `data-tenant` set, per `guidelines/tenant-onboarding.md`. Report results before calling it done.
5. **Check the cards after significant changes.** After edits to components, tokens, `components.css`, `styles.css` or the bundle layout, run `check_design_system` and screenshot the affected @dsCard cards (or all of Components + Colors when in doubt) and fix breakage before finishing.
