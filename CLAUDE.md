# Vendra Design System — working rules

1. **Templates are the source of truth.** `templates/storefront-*` is the official storefront. `ui_kits/storefront/` is a sandbox/demo: never port changes into it by default, and don't treat it as a spec. If a change touches both, do the templates first and only mirror into the kit when asked.
2. **Never hand-edit the shared shell in a template.** Header, footer, mobile menu and bottom tab bar for all 16 templates come from `scraps/vf-gen.js.txt`. Edit the generator, then regenerate all 16 via `run_script` (`eval(await readFile('scraps/vf-gen.js.txt'))`). Page-specific content inside `<main>` may be edited directly.
3. **Keep `_ds_bundle.js` lean.** Every `.js`/`.jsx` outside `templates/` is compiled into the bundle. Scratch scripts, generators and sample data must use a `.txt` suffix (loaded via `<script type="text/babel" src="….txt">`) or live under `templates/`. Shared runtime helpers go in `components/utils/`. Never put a second React/Babel copy outside `templates/_vendor/`.
4. **Tenant themes must pass contrast.** Any new or changed `tokens/tenants/*.css` must pass all six Theme builder checks (`guidelines/theme-builder.html`) and the Colors → Contrast card with `data-tenant` set, per `guidelines/tenant-onboarding.md`. Report results before calling it done.
5. **Check the cards after significant changes.** After edits to components, tokens, `components.css`, `styles.css` or the bundle layout, run `check_design_system` and screenshot the affected @dsCard cards (or all of Components + Colors when in doubt) and fix breakage before finishing.
