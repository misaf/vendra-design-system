# Live florist pilot audit

[Roadmap #363](https://github.com/misaf/vendra-design-system/issues/363) calls for one florist to fulfill a real order through the bilingual storefront, with recovery if the checkout response is lost. This audit covers the storefront after the [App Router migration](https://github.com/misaf/vendra-design-system/pull/361), the [florist template at `87d3ad5`](https://github.com/misaf/vendra-storefront-florist/tree/87d3ad53f91656f4307cac56ec4b613ea5846119), and [Laravel at `650c974`](https://github.com/misaf/vendra/tree/650c97403052b87a5fec7227a3a1f7183cfa5909). Findings come from source inspection and local Laravel tests. A deployed tenant, payment provider and fulfillment run still need verification.

## Deployment and ownership

- **The App Router migration gives the pilot a behavioral baseline.** The Next.js app is in [`src/app/`](../app/), its production config [exports static files](../next.config.mjs), and [CI](../.github/workflows/ci.yml) tests both languages under the Pages base path. [#364](https://github.com/misaf/vendra-design-system/issues/364) needs a server-capable build for runtime tenant and session handling alongside the static demo build. Verify both artifacts in CI and keep the published URLs independently of how the route files are organized.
- **The existing florist template already serves as a deployment model.** Its [provisioning contract](https://github.com/misaf/vendra-storefront-florist/blob/87d3ad53f91656f4307cac56ec4b613ea5846119/README.md#store-configuration) supplies one tenant per container from a shared image. Its [checkout](https://github.com/misaf/vendra-storefront-florist/blob/87d3ad53f91656f4307cac56ec4b613ea5846119/src/modules/checkout/README.md) is simulated. [#368](https://github.com/misaf/vendra-design-system/issues/368) explicitly calls for two domains on one live deployment. Record which repo and artifact the pilot will deploy and how its provisioning will supply host and API mappings in [#234](https://github.com/misaf/vendra-design-system/issues/234) before wiring tenancy in #364.
- **The reference catalog is fixture-backed.** [Catalog records](../src/storefront/catalog/catalog.js) are mapped from bundled samples, and [`apiBase`](../src/storefront/store/store-config.js) enables integrations. [#250](https://github.com/misaf/vendra-design-system/issues/250) must supply tenant catalog, settings and fulfillment inputs before the pilot accepts orders. Missing or unavailable live data needs an explicit error state. Keep fixture fallback in the reference demo.
- **The existing UI and theme generator give #366 a starting point.** [Component source](../src/design-system/components/) and [semantic tokens](../src/design-system/tokens/) are app-local today. Move only the shared primitives the pilot uses first. Keep theme validation, CSS layer ordering, EN/FA behavior and native attributes covered during extraction. Keep Laravel types and adapters in `packages/vendra-api`, with tenant and session setup in `src/app/_document/`. Laravel owns prices, stock, delivery availability, orders, payment verification and wallet balances.

## Laravel contract findings

The checked-in [OpenAPI snapshot](../tests/fixtures/vendra-openapi.json) still supports the demo fixture tests. Several gaps in [API alignment](./API.md) describe that snapshot. [#365](https://github.com/misaf/vendra-design-system/issues/365) should capture the response bodies, auth requirements and errors from the pilot's Laravel deployment before generating types.

| Area | Evidence in the audited Laravel source | Pilot acceptance |
| --- | --- | --- |
| Session and cart | [Cart resource](https://github.com/misaf/vendra/blob/650c97403052b87a5fec7227a3a1f7183cfa5909/packages/vendra-cart-api/src/ApiResource/CartResource.php) exposes authenticated list/detail. [Checkout](https://github.com/misaf/vendra/blob/650c97403052b87a5fec7227a3a1f7183cfa5909/packages/vendra-order-api/src/State/PlaceOrderProcessor.php) requires a nonempty, unexpired cart owned by the caller. | Agree on sign-in or a server-issued guest session. Verify cart creation and line writes, product-code and add-on mapping, server totals, and cart continuity across refresh and language change. |
| Delivery | [Quote processor](https://github.com/misaf/vendra/blob/650c97403052b87a5fec7227a3a1f7183cfa5909/packages/vendra-delivery-api/src/State/QuoteDeliveryProcessor.php) returns zone, distance, fee, currency and manual-quote flag. [Delivery API tests](https://github.com/misaf/vendra/blob/650c97403052b87a5fec7227a3a1f7183cfa5909/packages/vendra-delivery-api/tests/Feature/DeliveryApiTest.php) cover schedule reads. Checkout recomputes the fee and checks the date and active slot. | Agree on how checkout refers to the reviewed quote. Prove that a changed fee or a slot that closes before submission returns the shopper to review without placing an order. Use the store timezone on both sides. |
| Checkout and recovery | [Checkout processor](https://github.com/misaf/vendra/blob/650c97403052b87a5fec7227a3a1f7183cfa5909/packages/vendra-order-api/src/State/PlaceOrderProcessor.php) returns an order with server totals, reprices the cart and deducts stock transactionally. The storefront [sends an idempotency key](../src/platform/browser/integrations/idempotency.js). Server replay of an existing order was not established by the checkout operation or its [feature tests](https://github.com/misaf/vendra/blob/650c97403052b87a5fec7227a3a1f7183cfa5909/packages/vendra-order-api/tests/Feature/CustomerOrderApiTest.php). | Commit the first request and drop its response. Retry the same payload and key after reload. Require the same order number, one stock deduction, and no duplicate payment or notification. Cover an in-flight retry and a changed payload. |
| Tracking and payment | [Order resource](https://github.com/misaf/vendra/blob/650c97403052b87a5fec7227a3a1f7183cfa5909/packages/vendra-order-api/src/ApiResource/OrderResource.php) exposes authenticated list/detail and returns the order number. It has no payment status field. The [storefront return handler](../src/storefront/shell/routing.js) expects the order number in the URL. | Verify authorized lookup by number and the payment status for the florist's selected method. For a gateway, rehearse the callback, a return in a fresh tab and retry on the existing order. If guest tracking is offered, verify guest authorization and separate sender and recipient views. |

### Local checkout verification for #365

The cart, delivery and order API suites passed all 36 existing tests with in-memory SQLite. Two additional checks against the same Laravel checkout reproduced gaps in the pilot contract.

| What we ran | Observed result | Required behavior |
| --- | --- | --- |
| Seed an authenticated customer's cart with two units of a product that has ten in stock. Submit checkout, discard the response from the shopper's perspective, and submit the identical payload and `Idempotency-Key` again. | First request returned `201` with an order number. The retry returned `422` on `cartToken` because the first checkout emptied the cart. One order remained and stock was eight. | Return the existing order on replay. Resolve it before revalidating the cart consumed by the first request, and scope the key to the tenant and customer or session. |
| Quote a delivery fee of 1,500, raise the zone fee to 2,000, then submit the cart with the same destination and a bookable date and slot. | Checkout returned `201` and created one order with a delivery fee of 2,000. | Surface the changed quote for review before creating the order. Agree on the quote reference and error response, then cover expired quotes and closed slots in the same contract. |

Repeat both cases through the staging storefront once the pilot florist, payment method and staging access are confirmed. The local checks seeded carts directly and exercised Laravel's HTTP routes. Staging also needs to cover cart creation through the storefront and payment status for the selected method.

5. Schedule [#369](https://github.com/misaf/vendra-design-system/issues/369) and [#370](https://github.com/misaf/vendra-design-system/issues/370) around florist needs. Preserve existing counter links during cutover if the florist has distributed them. Verify one-time import, current pricing and [offline presentation](../e2e/smoke/export.spec.mjs) when the counter is in scope.
